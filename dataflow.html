lazyam - Data Flow Diagrams

Visual representations of data flow and processing pipelines in the lazyam automated media transcoding system.

1. Main Processing Cycle

The main application loop cycles through 6 stages: checking locks, loading caches, updating metadata, processing tasks, handling trailers, and sleeping between cycles. 
        graph TD
            A[[Start]] --> B[App Initialization]
            B --> C[Load Config]
            C --> D[Create AppContext]
            D --> E[Start Logging]
            E --> F{Cycle Loop}
            
            F --> G[Stage 1: CheckLock]
            G -->|Lock file exists| G
            G -->|Lock cleared| H[Stage 2: ReadCache]
            
            H -->|Cache exists| I[Load Project Cache]
            H -->|Cache exists| J[Load Task Cache]
            H -->|No cache| K[Create Empty Cache]
            K --> I
            
            I --> L[Stage 3: UpdateCache]
            L --> M[Read Metadata JSON Files]
            M --> N[Convert to Unified Format]
            N --> O[Save to Cache]
            
            O --> P[Stage 4: ProjectProcessing]
            P --> Q{For each task}
            Q --> R[SyncMeta + ScanSources]
            R --> S[Interlace Detection]
            S --> T[Generate Transcoding Script]
            T --> U[Move Sources]
            
            U --> V[Stage 5: TrailerProcessing]
            V --> W{Find *_a_teka.mp4}
            W -->|Found| X[Generate Trailer Script]
            W -->|Not found| Y[Stage 6: Sleep]
            X --> Y
            
            Y --> Z[Dormant Mode]
            Z --> F

2. Task Processing State Machine

Each task (media directory) progresses through a state machine with phases for metadata sync, source scanning, interlace checking, and transcoding. 
        stateDiagram-v2
            [*] --> NewTask: Discovered in input dir
            
            NewTask --> Phase_SyncMeta: Start processing
            Phase_SyncMeta --> Phase_SyncMeta: Collect signal files
            Phase_SyncMeta --> Phase_ScanSources: Metadata ready
            
            Phase_ScanSources --> Phase_ScanSources: ffprobe each file
            Phase_ScanSources --> Phase_StartInterlaceCheck: Sources scanned
            
            Phase_StartInterlaceCheck --> Phase_StartInterlaceCheck: Run idet filter
            Phase_StartInterlaceCheck --> Phase_EvaluateInterlaceCheckResult: Scan complete
            
            Phase_EvaluateInterlaceCheckResult --> Phase_EvaluateTrancecodingProcess: Evaluate ratio
            Phase_EvaluateTrancecodingResult --> Phase_EvaluateTrancecodingProcess: Done
            
            Phase_EvaluateTrancecodingProcess --> Phase_EvaluateTrancecodingProcess: Select template
            Phase_EvaluateTrancecodingProcess --> Phase_WaitTranceCodingResult: Generate .sh script
            
            Phase_WaitTranceCodingResult --> Phase_WaitTranceCodingResult: Wait for completion
            Phase_WaitTranceCodingResult --> Phase_CleanData: Script finished
            
            Phase_CleanData --> [*]: Task complete
            
            note right of Phase_SyncMeta
                Reads metadata.json
                Searches project cache
                Falls back to dir name
            end note
            
            note right of Phase_ScanSources
                Runs ffprobe via UMP
                Detects streams
                Validates format
            end note
            
            note right of Phase_StartInterlaceCheck
                Runs ffmpeg idet filter
                Parses .idet output
                Calculates ratio
            end note
            
            note right of Phase_EvaluateTrancecodingProcess
                Selects Amedia1/2/2S template
                Replaces placeholders
                Creates shell script
            end note

7. Cache Persistence & Recovery

How the application maintains state across restarts through JSON cache files. 
        sequenceDiagram
            participant App as lazyam
            participant PC as Project Cache
(projects.json)
            participant TC as Task Cache
(tasks.json)
            participant FS as File System
            participant Meta as Metadata JSON
            
            App->>App: Cycle Start
            App->>App: --keep-cache flag?
            
            alt Cache Exists
                App->>PC: Load projects.json
                App->>TC: Load tasks.json
                PC-->>App: ProjectPool + LastUpdate
                TC-->>App: TaskMap
            else No Cache
                App->>FS: Create empty projects.json
                App->>FS: Create empty tasks.json
                FS-->>App: Empty structures
            end
            
            App->>Meta: Read metadata files
            Meta-->>App: Movies/Series JSON
            
            App->>App: Convert to unified format
            App->>PC: Update/Inject projects
            App->>PC: Save projects.json
            
            loop For each task directory
                App->>App: Create Task{}
                App->>TC: Add task to map
                App->>TC: Save tasks.json
            end
            
            App->>App: Process tasks...
            App->>TC: Update task states
            App->>TC: Save tasks.json
            
            App->>App: Sleep (dormant mode)
            App->>App: Next cycle...
